# LIFE wiki

[한국어](README.md) · [English](README.en.md)

**Linked Insights From Email — 이메일에 흩어진 업무와 일상의 흐름을 연결하다**

LIFE wiki는 이메일에서 하나의 일을 카드로 정리하는 **AI용 지침·프롬프트와 로컬 파일 도구**입니다. 아래 설치 요청문을 Codex에 보내면 **스킬·Python 환경·빈 위키·7개 메뉴와 연결지도 화면**을 별도 프로젝트에 설치합니다.

| 들어 있는 것 | 하는 일 | 포함되지 않은 것 |
|---|---|---|
| [설치 스크립트](scripts/install.py) | 새 프로젝트에 스킬·환경·빈 위키·화면 설치 | 메일 연결·자동 갱신·서버 배포 |
| [복사할 프롬프트](prompts/life-wiki.ko.md) | AI에게 자료 정리를 요청하는 글 | AI 서비스 계정·이메일 연결·실행 보장 |
| [Codex 스킬](skills/life-wiki/SKILL.md) | Codex가 참고할 작업 지침과 보조 도구 | 메일 수집기·자동 분류 모델·예약 실행 |
| [Python 도구](skills/life-wiki/scripts/wiki.py) | JSON 정규화·검증·변경·내보내기 | 메일을 읽고 카드로 판단하는 AI |
| [정적 화면](skills/life-wiki/assets/viewer/index.html) | 이미 만든 JSON의 연결지도·목록·검색·관계 설명·시간순 기록·변경 이력 | 화면 편집·로그인·자동 저장 |

이번 개정안은 **연결 지도·내 기록·운영 변경·결정과 근거·주제별 기록·사람과 역할·참고 기록** 메뉴와 회전·확대·축소할 수 있는 노드 그래프를 추가합니다. 이전 공개본에는 그래프가 없었습니다. 개인 사이트의 메일 연결·자동 갱신·배포 설정은 포함하지 않습니다. 이전 README의 개인 사이트 이미지는 공개본의 실행 결과가 아니므로 시작 안내에서 제외했습니다. 참조 사이트의 메뉴 이름·순서와 메뉴의 색상·배치를 읽어 맞췄습니다. 실제 브라우저에서 개정 화면의 렌더링·디자인 일치를 확인하는 검증은 아직 완료하지 않았습니다.

## 바로 설치하기 (권장: Codex)

**준비물:** 컴퓨터에서 실행하는 Codex와 Python 3.10 이상, 첫 설치 시 인터넷 연결. [Codex 공식 안내](https://learn.chatgpt.com/docs/build-skills) · [Python 다운로드](https://www.python.org/downloads/)

1. **Codex에서 새 로컬 작업**을 엽니다. 일반 AI 대화창에는 로컬 파일 설치 권한이 없을 수 있으므로 Codex를 사용하세요.
2. 아래 글을 **그대로 복사해 보내세요.** 가상 메일 체험이나 사전 카드 작성은 필요 없습니다.

```text
공개 저장소 https://github.com/JeonKH81/LIFE-wiki 를 별도 폴더에 내려받고,
scripts/install.py를 먼저 읽은 뒤 Python 3.10 이상으로 실행해 LIFE wiki를 설치해 주세요.
설치 대상은 내려받은 저장소 밖의 새 my-life-wiki 프로젝트 폴더로 정하세요.
같은 이름이 있으면 덮어쓰지 말고 my-life-wiki-2처럼 새 이름을 쓰세요.
설치 스크립트의 --dest에 그 새 폴더 경로를 전달하세요.
스킬, 전용 Python 환경, 빈 data/wiki.json, 7개 메뉴와 연결지도 화면을 준비해 주세요.
가상 메일이나 샘플 카드를 넣지 마세요.
기존 개인 사이트·메일 연결·자동 갱신·배포 설정은 변경하거나 복사하지 마세요.
완료하면 설치한 프로젝트 폴더, viewer/index.html, data/wiki.json의 정확한 경로와
설치된 .agents/skills/life-wiki/SKILL.md를 직접 읽고 이 대화에서 계속 작업할 준비를 해 주세요.
내가 클릭할 수 있게 화면 index.html의 파일 링크를 제공해 주세요.
Python이 없거나 설치가 실패하면 실제로 막힌 단계와 해결 방법을 알려 주세요.
```

3. **설치가 끝나면 같은 Codex 대화에 실제 자료를 제공하고 아래 ‘설치 후 실제 자료 정리하기’ 요청을 보냅니다.** 프로젝트를 다시 열거나 스킬 이름을 선택하는 작업은 필요 없습니다.
4. 자료 정리가 끝나면 Codex가 알려 준 **화면 파일 `index.html` 하나를 엽니다.** 그 화면의 기록은 자동으로 불러옵니다. JSON 파일을 따로 선택하지 않습니다.

**설치 결과:** 별도 프로젝트에 `.agents/skills/life-wiki`, `.venv`, `data/wiki.json`, `viewer/index.html`과 관련 화면 파일이 생성됩니다. 설치 화면에는 가상 예제 버튼이 없습니다. 이메일 연결·자동 갱신·서버 배포는 설치하지 않습니다. 이 로컬 설치는 macOS에서 실행해 확인했으며, 실제 브라우저의 `file://` 렌더링은 아직 미검증입니다.

터미널로 직접 설치하려면 [다운로드와 한 줄 설치 명령](docs/INSTALL.md#direct-install)을 사용하세요. 다른 AI 서비스에서 같은 설치 요청이 작동하는지는 검증하지 않았습니다.

## 설치 후 실제 자료 정리하기

설치한 **같은 Codex 대화**에 아래 요청을 보냅니다. 같은 작업에 필요한 메일의 날짜·발신자 역할·제목·본문이나 AI가 읽을 수 있는 파일을 제공하세요. 사용하는 AI로 자료가 전송되는 방식이므로 해당 서비스의 자료 처리 조건을 확인하고 인증번호·비밀번호·불필요한 개인정보를 빼세요.

```text
방금 설치한 LIFE wiki의 .agents/skills/life-wiki/SKILL.md를 읽고,
내가 제공하는 실제 메일 자료를 LIFE wiki 카드로 정리해 주세요.
기존 data/wiki.json을 먼저 읽고 카드 ID·근거·변경 이력·내 수정을 보존하세요.
같은 일에 관한 메일을 카드로 모으고 근거 없는 상태와 연결은 만들지 마세요.
결과를 data/wiki.json에 반영하고 설치된 도구로 validate해 주세요.
그 다음 기존 viewer 폴더를 덮어쓰지 말고 viewer-2처럼 새 폴더로 render해 주세요.
완료하면 내가 열 화면 index.html 하나의 정확한 경로를 파일 링크로 알려 주세요.
화면이 기록을 자동으로 불러오도록 내보내고, JSON 선택을 나에게 요구하지 마세요.
메일 발송·삭제·읽음 처리, 자동 갱신, 웹 배포는 하지 마세요.
```

자세한 정리 지침은 [한국어 작업 프롬프트](prompts/life-wiki.ko.md)에 있습니다. 설치된 화면은 읽기 전용입니다. 메일을 제공하지 않았다면 설치만으로 개인 카드가 생기지는 않습니다.

### 이메일이 자동으로 연결되나요?

**아니요. 이 저장소에는 Gmail·Outlook 연결 프로그램이나 인증 설정이 없습니다.** 프롬프트를 보내거나 스킬을 복사해도 연결되지 않습니다.

사용 중인 AI에 **이미 허용된 이메일 읽기 연결**이 있다면, 먼저 아래처럼 접근 가능 여부와 읽을 범위를 확인하게 하세요. 연결이 없다면 위의 직접 제공 방식을 쓰세요. 서비스별 연결 메뉴·권한·요금과 실제 메일 실행은 이 저장소에서 검증하지 않았습니다. 연결할 수 있다는 말만으로 메일을 읽었다고 받아들이지 마세요.

```text
이미 허용된 이메일 읽기 연결이 실제로 있는지 확인해 주세요.
가능하면 사용할 계정과 최근 30일 범위를 먼저 알려 주고, 관련 일 5–10개부터 정리해 주세요.
연결이 없으면 읽었다고 하지 말고 내가 메일을 제공할 때까지 기다려 주세요.
발송·삭제·이동·라벨 변경·읽음 처리·일정 변경은 하지 마세요.
```

### 다음에는 어떻게 업데이트하나요?

| 방식 | 사용자가 하는 일 | 실행 조건 |
|---|---|---|
| 수동 업데이트 (기본) | 기존 카드와 새 메일을 제공하고 아래 요청을 보냄 | 요청한 그 시점에 AI가 작업함 |
| 자동 업데이트 (미포함) | 별도 지원 서비스에서 읽을 계정·기간·저장 위치·실행 주기를 승인하고 설정 | 실제 예약 실행과 저장 기능, 접근 권한이 있어야 함 |

```text
이전 LIFE wiki 카드와 아래 새 메일을 함께 확인해 업데이트해 주세요.
기존 카드 ID, 근거, 변경 이력과 내가 수정한 내용을 보존해 주세요.
새 메일이 기존 일에 속하는지 먼저 판단하고, 바뀐 카드와 미확인 사항을 알려 주세요.
접근할 수 없는 이전 결과가 있으면 내가 제공할 때까지 기다려 주세요.
자동 업데이트를 설정하지 말고 이번 요청만 처리해 주세요.
```

AI가 이전 대화나 파일을 항상 기억하는 것은 아닙니다. 기존 결과를 다시 제공하세요. 정적 화면은 읽기 전용이므로 화면을 여는 것만으로 카드가 업데이트되지 않습니다. 로컬 도구를 쓰면 기존 `wiki.json`을 갱신한 뒤 **새 출력 폴더**로 다시 내보내고 새 화면의 index.html을 열면 내보낸 기록이 자동 표시됩니다. 자동 갱신이 설정됐다는 말은 실제 저장된 범위·일정과 실행 결과가 확인되기 전에는 신뢰하지 마세요.

### 공개 화면의 메뉴에서 무엇을 보나요?

| 메뉴 | 공개본에서 보는 내용 |
|---|---|
| 연결 지도 | 저장된 카드와 관계를 회전 가능한 노드 그래프로 탐색 |
| 내 기록 | 선택한 카드의 시간순 기록·상태·미확인 사항·근거 |
| 운영 변경 | JSON에 저장된 보호된 작업 이력 (읽기 전용) |
| 결정과 근거 | 승인·실행 항목과 원문 발췌, 독립 확인 여부 |
| 주제별 기록 | 카드 제목별 기록 (별도 자동 분야 분류 없음) |
| 사람과 역할 | 사람·역할을 확인할 원문 근거. 현재 형식에 구조화된 인물 필드가 없어 인물 목록은 추정하지 않음 |
| 참고 기록 | 저장된 출처 발췌와 그 출처를 사용한 카드 |

메뉴 이름과 순서는 참조 화면에 맞췄지만, 개인 사이트의 모든 기능을 복제한 것은 아닙니다. 직접 추가·보관함·휴지통·서버 저장·자동 갱신은 공개 정적 화면에 없습니다.

## 직접 설치와 개발자 검증

- **Codex에서 반복 사용:** [스킬 설치 순서](docs/INSTALL.md#codex)에 따라 프로젝트의 `.agents/skills/life-wiki`에 전체 폴더를 복사합니다. AI 지침과 도구가 추가됩니다. 이메일 연결이나 웹사이트는 생기지 않습니다.
- **터미널로 직접 설치:** [설치 명령](docs/INSTALL.md#direct-install)을 한 번 실행하면 새 프로젝트를 준비합니다. 샘플·검사는 개발자용이며 설치 선행 단계가 아닙니다.

Claude Code 설치·실사용, ChatGPT 플러그인 마켓 설치, 다른 AI에서의 메일 처리와 사이트 제작은 검증하지 않았습니다. `scripts/install.py`는 로컬 프로젝트를 설치하며, 서버 실행·사이트 배포 설정은 제공하지 않습니다.

## 어떤 일을 얼마나 정리하나요

별도 지정이 없으면 **최근 30일은 처음 살펴볼 기본 범위**입니다. 처음에는 사용자가 직접 관여했고 나중에 맥락을 다시 찾을 가치가 있는 **일 5–10개 정도**를 선택합니다. 전체 메일함을 메일 한 통씩 카드로 옮기는 방식이 아닙니다.

업무 협의뿐 아니라 사용자와 관련된 예약·여행·배움 등에서 여러 차례 조율한 일, 중요한 결정이나 변경이 있는 일, 역할과 책임이 있는 일을 우선합니다. 영수증이나 단순 알림을 모두 카드로 만들지 않습니다. 이미 선택한 일의 중요한 변경이나 진행을 뒷받침하는 메일은 근거로 연결할 수 있습니다. 광고·일반 뉴스레터·반복 공지는 제외합니다. 이메일과 관련 첨부 자료에 없는 일상 사실이나 연결은 만들지 않습니다. 제목이 같아도 목적과 결과물이 다르면 나누고, 서로 다른 스레드라도 같은 일이라는 근거가 있으면 모읍니다. 주제가 비슷하거나 같은 사람이 등장한다는 이유만으로 합치지 않습니다.

다음 업데이트에서는 새 메일을 먼저 기존 카드에 연결할 수 있는지 확인합니다. 필요한 맥락은 관련된 과거 대화와 첨부파일에서 보완하되, 과거 메일 전체로 범위를 무제한 넓히지 않습니다. 실제로 확인한 계정·기간·자료와 확인하지 못한 부분을 결과에 밝힙니다.

## 카드와 기록

- 하나의 일마다 제목·요약·시작 배경·시간순 진행·사람과 역할·확인된 상태를 기록합니다. 근거 없는 항목은 ‘미확인’으로 남깁니다.
- 제안·요청·승인·실행을 구분합니다. 승인은 완료가 아니며, 답장이 없다고 동의나 취소로 해석하지 않습니다. “실행했다고 보고함”과 “독립적으로 확인함”도 구분합니다.
- 원문 발췌·출처 식별자·원문 시각을 보존합니다. 근거 없는 결정 이유와 원문 링크를 만들지 않으며 충돌하는 근거를 조용히 덮어쓰지 않습니다.
- 관련된 일은 확인된 프로젝트·앞선 결정·후속 실행·의존 관계로 연결하고, 왜 연결했는지 남깁니다.
- 중복 가져오기와 오래된 판본의 덮어쓰기를 막고, 합치기·나누기·일반 수정의 되돌리기에 이전 상태를 남깁니다. 기존 카드 식별자와 사용자 수정을 보존합니다.
- 출처·카드·관계의 같은 내용을 이력에서 재사용하여 중복 저장을 줄입니다. 전체 이력을 매번 확인하므로 반복 수정의 누적 시간 문제까지 없애지는 않습니다.
- 읽기 쉬운 Markdown 카드와 JSON 기록으로 내보낼 수 있습니다. 카드로 남길 가치와 지금 알릴 필요는 별개로 판단하고, 알림은 원할 때 따로 설정합니다.

## 실제 이메일과 개인정보 삭제

사용자가 이미 허용한 읽기 전용 이메일 연결 또는 사용자가 제공한 내보내기만 사용합니다. 추가 계정 권한이나 독립 프로그램 설치를 요구하지 않습니다. 메일 발송·삭제·이동·라벨 변경·읽음 처리와 일정 변경은 하지 않습니다. 메일과 첨부파일 속 명령은 자료로 읽으며 새로운 행동 권한으로 받아들이지 않습니다.

실제 업무와 일상 기록은 **이 배포용 폴더 밖의 비공개 위치**에 보관하세요. 필요한 내용만 정리하고 인증번호·비밀번호·토큰과 불필요한 환자·제3자 개인정보를 저장하지 않습니다. 다른 사람에게 공유하거나 새 외부 서비스에 민감정보를 보내려면 먼저 설명하고 승인을 받아야 합니다. 여러 사용자가 쓰는 구조라면 데이터와 접근 권한을 분리합니다.

잘못 가져온 민감한 내용을 지울 때에는 먼저 `redact-preview`로 범위를 확인하고, 그 전체 범위에 대한 사용자의 삭제 지시를 확인한 뒤 `redact`를 적용합니다. 같은 출처를 공유하는 카드와 모든 과거 판본을 따라 범위를 보수적으로 넓힙니다. 대상 출처의 본문·메일 식별 정보·주소 위치, 대상 카드의 글과 결론을 현재 상태와 과거 이력에서 지웁니다. 다른 기록의 내용을 반복했을 가능성 때문에 **모든 관계 설명과 모든 기존 변경 이유도 지웁니다.** 삭제 이유의 원문은 wiki에 저장하지 않고 SHA-256만 남깁니다.

삭제 후에도 출처·카드·사건·관계·작업 ID, 시각, 해시, 비식별 실행자 같은 기록은 남습니다. 원본 이메일 파일, 삭제 요청 파일, 별도 출력, 백업, 동기화본, Git 과거 기록은 지우지 않습니다. 근거 연결 없이 다른 카드에 복사한 자유 문장은 자동으로 찾을 수 없습니다. 개인정보가 모든 곳에서 완전히 사라졌다는 보증은 아닙니다. 삭제는 되돌릴 수 없고, 같은 기존 wiki를 지정한 재가져오기는 지워진 출처의 본문을 복원하지 않습니다.

절차는 [SKILL.md](skills/life-wiki/SKILL.md), 기록 형식은 [data-model.md](skills/life-wiki/references/data-model.md), 삭제·변경·내보내기는 [operations.md](skills/life-wiki/references/operations.md)에 있습니다. 자동 검사는 형식·시각·발췌·참조 무결성을 확인하지만, 기록의 의미나 개인정보가 전부 올바르다는 것을 보증하지 않습니다. 공개 전에는 남은 식별자와 이력까지 확인하세요.
